# 변경 이력 — 2026-05-22

## 현재 시스템 구조

```
[동기 — HTTP 요청 내]
POST /upload (file, sourceLang, processMode, translatePrompt?, summaryPrompt?)
  → SHA-256 해시 + processMode별 중복 체크 (비관적 락)
  → PDFBox 텍스트 추출
  → DB 저장 (status=PROCESSING, processMode, llmProvider, customTranslatePrompt?, customSummaryPrompt?)
  → 즉시 반환

[비동기 — pdfTaskExecutor]
  → GeminiQuotaMonitor 확인: quota 소진 시 즉시 LOCAL로 라우팅
  → doc.llmProvider에 따라 LLM 서비스 선택:
      LOCAL  → VllmService (EXAONE/Qwen)
      CLAUDE → ClaudeService (Anthropic API)
      GEMINI → GeminiService (Google API, quota 소진 감지 포함)
  → processMode에 따라 번역/요약/번역+요약 수행
      커스텀 프롬프트 있으면 해당 시스템 프롬프트 사용, 없으면 기본값
  → Gemini 청크 처리 중 quota 소진 → onErrorResume → LOCAL로 즉시 전환
  → DB 업데이트 (status=DONE, translatedText, summary, llmProvider)

[Gemini → LOCAL Fallback 상세]
  1. GeminiService.callAsync(): quota 이미 소진 → 즉시 GeminiQuotaExhaustedException
  2. GeminiService.callAsync(): 429 응답 5회 재시도 후 → quotaMonitor.markExhausted() → GeminiQuotaExhaustedException
  3. PdfAsyncProcessor: 청크별 onErrorResume(GeminiQuotaExhaustedException) → vllmService로 fallback
  4. 최종 요약: try-catch(GeminiQuotaExhaustedException) → vllmService.summarize()
  5. 1시간 후 GeminiQuotaMonitor 자동 해제 → 다음 요청부터 Gemini 재사용

[학습 데이터 수집]
  → external-llm.provider=CLAUDE 또는 GEMINI 설정
  → GET /api/pdf/training/export → JSON 배열 (Alpaca 형식)
```

## 작업 이력

### [보고서] 전체 시스템 HTML 보고서 + SVG 워크플로우 업데이트

- **이유**: 팀 내부 보고 및 시스템 현황 공유 필요
- **변경 파일**:
  - `docs/system-report.html` — 신규 생성. 전체 시스템 현황, LLM 제공자 비교, 파이프라인, API 명세, 인프라, 작업 현황 포함
  - `docs/pdf-summary-workflow.svg` — Claude/Gemini 추가, Gemini→LOCAL fallback 흐름, 커스텀 프롬프트, 학습 데이터 파이프라인 반영
- **결과**: 브라우저에서 `docs/system-report.html` 을 열면 전체 시스템을 시각적으로 파악 가능

### [기능] Gemini → LOCAL 자동 Fallback 구현

- **이유**: Gemini 무료 티어 일일 할당량(500 RPD) 소진 시 서비스 FAILED 처리 없이 자동으로 GB10 로컬 모델로 전환
- **변경 파일**:
  - `service/GeminiQuotaMonitor.kt` — 신규. 할당량 소진 상태 추적 (1시간 캐시)
  - `service/GeminiQuotaMonitor.kt` — `GeminiQuotaExhaustedException` 클래스도 이 파일에 포함
  - `service/GeminiService.kt` — `GeminiQuotaMonitor` 주입, quota 소진 즉시 반환 로직, 5회 재시도 후 429 → markExhausted() + GeminiQuotaExhaustedException throw
  - `service/PdfAsyncProcessor.kt` — `GeminiQuotaMonitor` 주입, `llmFor()` 에서 quota 상태 체크, 청크별 `onErrorResume(GeminiQuotaExhaustedException)` → vllmService fallback, 최종 요약 try-catch fallback
- **결과**: Gemini 할당량 소진 시 현재 처리 중인 청크부터 즉시 LOCAL로 전환. 다음 요청도 1시간 내 자동 LOCAL 유지. 할당량 복구 후 Gemini 재사용.

### [기능] 커스텀 프롬프트 지원

- **이유**: 문서 유형(법률/의학/특허 등)에 따라 번역·요약 스타일을 세분화하고 싶은 요구
- **변경 파일**:
  - `domain/PdfDocument.kt` — `customTranslatePrompt`, `customSummaryPrompt` 필드 추가 (TEXT, nullable)
  - `schema.sql` — `ALTER TABLE` 2개 추가
  - `service/LlmService.kt` — `translateAsync`, `summarizeAsync` 에 `customPrompt: String? = null` 파라미터 추가
  - `service/VllmService.kt` / `ClaudeService.kt` / `GeminiService.kt` — 커스텀 프롬프트 있으면 시스템 프롬프트 대체, 없으면 기본값
  - `service/PdfAsyncProcessor.kt` — `customTranslatePrompt`, `customSummaryPrompt` 를 doc에서 읽어 LLM 호출에 전달
  - `service/PdfService.kt` — `upload()` 에 `customTranslatePrompt`, `customSummaryPrompt` 파라미터 추가
  - `controller/PdfController.kt` — `translatePrompt`, `summaryPrompt` 선택적 파라미터 추가
  - `controller/PageController.kt` — `translatePrompt`, `summaryPrompt` 선택적 파라미터 추가
  - `templates/index.html` — 업로드 폼에 `<details>` 접힘 섹션으로 커스텀 프롬프트 입력 추가
  - `static/css/style.css` — 커스텀 프롬프트 섹션 CSS 추가
- **결과**: 업로드 폼에서 "프롬프트 커스터마이즈" 클릭 후 번역/요약 프롬프트 직접 입력 가능. 비워두면 기존 하드코딩 기본값 동작.
