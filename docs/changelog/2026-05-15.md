# 변경 이력 — 2026-05-15

## 현재 시스템 구조

```
[동기 — HTTP 요청 내]
POST /upload (file, sourceLang, processMode)
  → SHA-256 해시 + processMode별 중복 체크 (비관적 락, FOR UPDATE)
      이미 같은 결과 있으면 → CACHED → /detail/{id} 리다이렉트
  → PDFBox 텍스트 추출 (~1-2초)
  → DB 저장 (status=PROCESSING, processMode 저장)
  → 즉시 반환 (HTTP 응답 종료)

[비동기 — pdfTaskExecutor (core=2, max=4)]
  processMode에 따라 분기:

  TRANSLATE:
    → 청크 분할 (최대 2500자, 300자 오버랩)
    → 병렬 번역 (concurrency=10)
       EN → EXAONE 3.5 32B AWQ / ZH·JA → Qwen 2.5 14B
    → DB 업데이트 (status=DONE, translatedText)

  SUMMARIZE:
    → 기존 번역본 있으면 fast-track (번역 단계 스킵, 한국어 소요약 사용)
    → 없으면 원문 직접 소요약 (각 언어별 모델 라우팅)
    → 소요약 합산 (최대 4000자) → 최종 요약 (Qwen 14B, maxTokens=1500)
    → DB 업데이트 (status=DONE, summary)

  BOTH:
    → 기존 번역본 있으면 fast-track (번역 단계 스킵)
    → 없으면 TRANSLATE 단계 수행
    → 번역본을 5000자 청크로 분할 → 소요약 병렬 생성 (concurrency=4)
    → 소요약 합산 → 최종 요약
    → DB 업데이트 (status=DONE, translatedText, summary)

[안전장치]
  → @Scheduled (1분마다): PROCESSING 상태가 30분 초과 시 FAILED 자동 전환
  → UI: PROCESSING 문서 존재 시 5초마다 자동 새로고침
  → FAILED 문서: UI에서 원클릭 재시도 가능
```

## 작업 이력

### [기능] ProcessMode 3버튼 선택 기능 구현
- **이유**: 사용자마다 번역만 필요하거나 요약만 필요한 경우가 다름
- **변경 파일**:
  - `domain/ProcessMode.kt` (신규) — TRANSLATE / SUMMARIZE / BOTH enum (displayName 포함)
  - `domain/PdfDocument.kt` — processMode 필드 추가 (기본값 BOTH)
  - `resources/schema.sql` — process_mode 컬럼 추가
  - `service/VllmService.kt` — `summarizeFromSourceAsync()` 추가 (원문 언어 직접 소요약)
  - `service/PdfAsyncProcessor.kt` — processMode 분기 (doTranslate / doSummarize / doTranslateAndSummarize)
  - `service/PdfService.kt` — upload()에 processMode 파라미터 추가
  - `controller/PdfController.kt` / `PageController.kt` — processMode 파라미터 수용
  - `dto/PdfUploadResponse.kt` / `PdfSummaryResponse.kt` — processMode 필드 추가
  - `templates/index.html` — 3버튼 UI (번역=파랑, 요약=초록, 번역/요약=보라)
  - `templates/detail.html` — processMode 기반 조건부 렌더링
- **결과**: processMode별 최적 처리 경로 실행

### [기능] 스마트 캐시 — processMode별 중복 체크 + fast-track
- **이유**: 같은 PDF를 번역 후 요약 요청 시 번역 단계를 재활용해야 함
- **동작**:
  - TRANSLATE 완료 후 SUMMARIZE 요청 → 번역본 재사용, 요약 단계만 실행 (fast-track)
  - 같은 파일 + 같은 모드 재업로드 → CACHED → 기존 결과 페이지로 리다이렉트
- **변경 파일**:
  - `repository/PdfDocumentRepository.kt` — `findAllByFileHashForUpdate()` (List 반환)
  - `service/PdfService.kt` — 모드별 CACHED 조건 분리 + fast-track 감지
  - `service/PdfAsyncProcessor.kt` — fast-track 분기 처리
  - `controller/PageController.kt` — CACHED 시 `/detail/{id}` 리다이렉트 + 안내 메시지
  - `templates/detail.html` — flash 메시지 표시 영역 추가

### [UI] 언어·모드 셀 줄바꿈 버그 수정

## Docker 배포 사용법

### 사전 준비 (최초 1회)
```bash
# application-dev.yaml 생성 (application-local.yaml 내용 동일하게 복사)
cp src/main/resources/application-local.yaml src/main/resources/application-dev.yaml
```

### 실행 명령어
```bash
# 처음 실행 or 코드 변경 후
docker compose up --build -d

# 로그 확인
docker compose logs -f app

# 중지 (데이터 유지)
docker compose down

# 재시작 (코드 변경 없을 때)
docker compose restart app
```

### 다른 PC에서 배포하려면
1. Docker Desktop 설치 (Windows) 또는 `curl -fsSL https://get.docker.com | sh` (Linux)
2. `git clone [레포]` 후 `cd pdf-summary`
3. `src/main/resources/application-dev.yaml` 파일을 같은 경로에 복사 (git에 없음 — 직접 전달)
4. `docker compose up --build -d`

### 접속
- 같은 네트워크: `http://[실행PC의IP]:8880`
- IP 확인: `ipconfig` (Windows) / `ip addr` (Linux)
