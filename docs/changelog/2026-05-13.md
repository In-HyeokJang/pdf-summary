# 변경 이력 — 2026-05-13

## 현재 시스템 구조

```
PDF 업로드 → 텍스트 추출 (PDFBox)
         → 청크 분할 (문단 경계 기준, 최대 2500자)
         → 각 청크 병렬 번역 (EN→EXAONE 3.5 32B AWQ :8001, ZH/JA→Qwen 14B :8000)
         → 번역본 합치기
         → 번역본 앞 6000자로 한국어 요약 (Qwen 14B :8000)
         → DB 저장 (PostgreSQL)
```

---

## 작업 이력

### [버그] @Lob 어노테이션으로 인한 PostgreSQL LOB 스트림 에러
- **이유**: `PdfDocument.kt`의 `originalText`, `translatedText`, `summary` 필드에 `@Lob`이 붙어 있어, PostgreSQL이 이를 Large Object(OID)로 처리함. LOB는 트랜잭션 없이(auto-commit mode) 읽을 수 없어 업로드 시 500 에러 발생.
- **에러**: `PSQLException: Large Objects may not be used in auto-commit mode`
- **변경 파일**: `PdfDocument.kt` — `@Lob` 3개 제거. `columnDefinition = "TEXT"`로 이미 PostgreSQL TEXT 타입을 명시했으므로 `@Lob` 불필요.
- **결과**: 업로드 정상 동작

### [개선] 요약 타이밍 로그 추가
- **이유**: 번역 단계는 청크별 로그가 있지만 요약 단계는 어떤 모델이 처리하는지, 입력 크기가 얼마인지 로그가 없었음
- **변경 파일**: `VllmService.kt` — `summarizeAsync()` 시작 시 모델명/입력 크기 로그 추가
